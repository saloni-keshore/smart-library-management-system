# Static Assets

No build step — all CSS/JS is hand-authored and served directly via `url_for('static', ...)`. Base framework is Bootstrap 5.3.7 + Bootstrap Icons 1.11.3, both loaded from CDN in `templates/layouts/base.html` / `auth_base.html` (not vendored locally).

## `static/charts/` — removed (2026-08-28, ADR-56)

This directory and its three server-generated PNGs (`revenue.png`, `membership.png`, `membership_distribution_donut.png`) are gone. `utils/charts.py` (matplotlib) was deleted; the Dashboard "Revenue Overview" / "Membership Distribution" and the Membership Distribution page's donut now render client-side with Chart.js from `{labels, datasets}` payloads built per-request, admin-scoped, by `utils/chart_data.py` (`build_revenue_chart_data` / `build_membership_chart_data` / `build_plan_distribution_chart_data`) and passed to the templates as `window.*` globals. Nothing is written to disk, which resolves the old shared-filename cross-tenant leak (**TD-1 Resolved**).

## `static/uploads/`

**Legacy-read-only as of 2026-08-28 (ADR-57).** Nothing writes here any more: `routes/setting.py`'s `_save_upload()` now uploads logo/stamp/signature to a public Supabase Storage bucket (`library-branding`) via `database/branding_storage.py`, and `library_settings.*_path` holds the full public URL. `static/uploads/settings/` (plus its `.gitkeep`) and any files still in it are pre-migration artifacts — `templates` render them through `utils/branding.py`'s `branding_src()`, which resolves a legacy `uploads/settings/x.png` value to `/static/uploads/settings/x.png` until the row is re-uploaded or `scripts/migrate_branding_to_storage.py` is run.
